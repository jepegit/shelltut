# 14 — GitHub CLI (`gh`)

Docs: [cli.github.com](https://cli.github.com/) · `gh help` · `gh help reference`

`gh` is the official GitHub CLI: repos, issues, PRs, Actions, and the REST/GraphQL API from your terminal.

## Goals

Authenticate, inspect this repo, search GitHub, work with issues/PRs, and pull JSON for scripting (pairs well with [jq](10-jq.md)).

## Setup

```bash
gh --version
gh auth status
```

If you are not logged in:

```bash
gh auth login
```

Follow the prompts (HTTPS or SSH; browser or token). Re-check with `gh auth status`.

Work from the `shelltut` clone so `gh` can infer the repo from `origin`:

```bash
cd /path/to/shelltut
git remote -v
```

## Drills — repo & browse

1. View this repository’s metadata:

```bash
gh repo view
gh repo view --json name,owner,url,description,defaultBranchRef
```

2. List your repos and clone nothing destructive — just look:

```bash
gh repo list --limit 10
gh repo list jepegit --limit 10
```

3. Open pages in the browser (or print the URL with `--no-browser` if you prefer):

```bash
gh browse
gh browse --no-browser
gh browse README.md --no-browser
```

4. Check what needs attention across repos you care about:

```bash
gh status
```

## Drills — search

1. Search repositories:

```bash
gh search repos "shell terminal training" --limit 5
gh search repos --owner jepegit --limit 10
```

2. Search code or issues on GitHub (read-only exploration):

```bash
gh search code "herdr pane run" --limit 5
gh search issues "good first issue" --repo cli/cli --limit 5
```

## Drills — issues (safe practice)

Prefer a throwaway issue on a repo you own, or skip create/close if you do not want noise on `shelltut`.

1. List issues:

```bash
gh issue list
gh issue list --state all --limit 20
```

2. Create, view, then close a practice issue (only on a repo you control):

```bash
gh issue create --title "shelltut practice: ignore" \
  --body "Temporary issue for learning \`gh\`. Safe to close."
gh issue view <number>
gh issue close <number> --reason completed
```

3. JSON for scripting:

```bash
gh issue list --json number,title,state,author --jq '.[] | "\(.number)\t\(.title)"'
```

## Drills — pull requests

Use a practice branch (see [git](11-git.md)). Only open a PR if you intend to; you can stop after `gh pr create --dry-run` style exploration, or create and close.

1. Inspect PR commands and list existing PRs:

```bash
gh pr --help
gh pr list
gh pr status
```

2. On a practice branch with a commit ahead of `main`:

```bash
git switch -c practice/gh-$(date +%Y%m%d)
# make a tiny change under playground/scratch/, commit, push
git push -u origin HEAD
gh pr create --title "practice: gh drill" --body "Training PR; safe to close." --draft
gh pr view
gh pr diff
gh pr checks   # if Actions exist
gh pr close --delete-branch
```

Skip the create/close steps if you do not want a remote branch; still run `gh pr list` and `gh pr view` on any public repo:

```bash
gh pr list --repo cli/cli --limit 5
gh pr view 1 --repo cli/cli
```

## Drills — API & formatting

1. Raw REST with pretty JSON:

```bash
gh api user
gh api repos/jepegit/shelltut --jq '.stargazers_count, .default_branch'
gh api repos/jepegit/shelltut/commits --jq '.[0].commit.message'
```

2. Learn export flags used across commands:

```bash
gh help formatting
gh repo view --json name,url -q '.url'
```

## Stretch

- Releases: `gh release list --repo cli/cli`
- Actions: `gh workflow list`, `gh run list` (on a repo that has workflows)
- Gists: `gh gist create playground/notes.txt -d "shelltut note"` then `gh gist list` / delete when done
- Completions: `gh completion -s bash` (or zsh/fish) and wire into your shell
- Aliases: `gh alias set bugs 'issue list --label bug'` then `gh bugs`

## Check yourself

From the `shelltut` directory you can run `gh repo view`, search with `gh search`, and pull a field via `gh api ... --jq` without opening the GitHub website.
